# Схема до июля

Недельный трекер результата: кривые вместо галочек, план с датой, экран «до / после».
Один статический файл плюс Supabase для данных. Работает с телефона, ставится на домашний экран.

## Что внутри

- `index.html` — всё приложение: четыре экрана (Графики, Запись, Правила, До / после)
- `config.js` — адрес проекта и publishable key, общие для всех устройств
- `supabase.sql` — таблицы и политики доступа
- `manifest.webmanifest`, `icon.svg` — чтобы ставилось иконкой на телефон

## Настройка, один раз

**1. База.** Создай бесплатный проект на supabase.com. Открой SQL Editor → New query,
вставь целиком `supabase.sql`, Run. Это создаст четыре таблицы, включит RLS
и выдаст роли `authenticated` права на таблицы. RLS привязывает каждую строку
к твоему логину; без грантов PostgREST отвечает `permission denied for table`,
не доходя до политик.

**2. Почтовый вход.** Authentication → Sign In / Providers: Email включён по умолчанию,
«Confirm email» можно оставить как есть. В Authentication → URL Configuration добавь
адрес сайта (см. шаг 3) в Site URL и в Redirect URLs.

**3. Хостинг.** Settings → Pages в этом репозитории: Source — Deploy from a branch,
ветка `main`, папка `/ (root)`. Через минуту сайт будет по адресу
`https://<логин>.github.io/<репозиторий>/`.

**4. Подключение.** Открой `config.js` в репозитории и впиши две строки из
Supabase → Project Settings → API Keys: `url` — Project URL, `key` —
**publishable key** (`sb_publishable_…`). Тогда шага «Подключить базу» не будет
ни на одном устройстве: открыл сайт — сразу вход по почте.

Если `config.js` оставить пустым, приложение спросит те же две строки на первом
экране и запомнит их в том браузере, где ввёл, — и спросит снова на телефоне.

Secret keys в браузер класть нельзя ни в каком виде. Дальше почта → приходит ссылка → вход.
Ключи и сессия лежат в localStorage устройства, в репозиторий не попадают.

На телефоне: открыть сайт в браузере → «На экран Домой». Дальше открывается как приложение.

## Почему anon key не секрет

Он публичный по замыслу Supabase. Доступ к данным закрывает не ключ, а RLS:
политики из `supabase.sql` разрешают читать и писать только строки,
где `user_id = auth.uid()`. Без входа по твоей почте ключ не даёт ничего.

## Устройство данных

| Таблица | Что лежит |
|---|---|
| `metrics` | метрики: название, единица, способ счёта (`level` — текущее значение, `sum` — прибавка за неделю), цель и дата |
| `weeks` | одна строка на неделю: `vals` — значения по id метрик, `note` — заметка |
| `rules` | карточки «если — то» |
| `marks` | левая половина экрана «до / после» |

Правая половина «после» не хранится: она каждый раз считается из `weeks` и `metrics`.
Вписать туда что-то руками нельзя по замыслу.
